# PCOS 90 Days — V1.5

纯前端、localStorage 驱动的 90 天 PCOS 生活方式管理 Dashboard。

## V1.5 更新

- 新增「💩 poop了吗？」：是 / 否 / 未记录严格区分；没有记录不会自动当作否；同一天可以反复修改且只保留一个最终状态。
- 补记入口先选择「今天 / 昨天 / 选择日期」，然后选择体重、饮食、运动、睡眠、身体状态或排便。日期选择器使用原生 input type=date，范围固定为 2026-09-23 至设备本地今天。
- 选定日期后显示「正在补记 · X月X日」；六类表单共享 selectedDate，保存后返回同一天的补记项目菜单，不必反复选日期。
- 补记表单使用进入时捕获的目标日期；饮食及排便历史编辑锁定原日期。保存函数再次校验日期，拒绝未来日期、计划开始前日期及无效日期。
- 历史查看保留今天、昨天、任意日期选择，并新增历史饮食编辑及排便修改入口。
- 21:00 今日分析新增排便事实摘要：今日已排便 / 今日记录为未排便 / 今日未记录排便情况。不根据单日排便状态作疾病判断。排便修改会同步更新当天已生成分析中的排便段落。
- 使用独立命名的 openRecord 打开记录表单，避免内联事件中的 open 与浏览器内置方法冲突。
- 保留 V1.4 手动热量 / ChatGPT估算、本地食物库、睡眠、21:00 解锁、长按删除、deleted tombstones、一次性旧版迁移及 JSON 合并导入；未新增药物 UI。

## 排便数据及兼容策略

永久主库仍为 `pcos90-data`，schema 更新为 6；没有新的版本化主库。旧数据缺少 `poop` 时只初始化为空数组，其余现有集合和 settings 保留。

新增字段示例：

```json
{
  "poop": [
    { "date": "2026-09-23", "value": false, "updatedAt": "2026-09-25T14:00:00.000Z" }
  ]
}
```

- value 为 true 表示是，false 表示否；日期没有条目表示未记录，不用 false 代替未记录。
- 每个日期一条最终记录。updatedAt 仅用于判断修改先后，不决定记录归属日期。
- 修改保留旧修订的删除标记，防止旧备份重新导入旧状态。合并时按日期去重，较新的 updatedAt 优先；相同时间保留本地状态。
- JSON 导出包含 poop 和 deleted；导入、刷新及已完成的一次性迁移都使用相同规范化逻辑。
- 重新记录体重或睡眠、修改饮食内容时保留旧记录的删除标记，防止旧版本内容被备份重新带回。
- 不调用 localStorage.clear()，不删除旧版 key，不重新扫描已完成迁移的旧库；旧 pills 字段仅保留兼容，不提供药物入口。

## 验证记录

使用独立测试数据完成 16 组逻辑回归，覆盖旧库加载、一次性迁移、排便三态与反复修改、六类 2026-09-23 补记、历史饮食/排便编辑日期锁定、未来/无效日期拒绝、手动区间/单值热量及 ChatGPT 来源、本地食物估算、21:00 分析门槛、排便摘要、deleted tombstones、旧备份合并、实际导入导出处理函数及重新加载持久化。

浏览器实测完成日期优先的补记流程，连续保存 9 月 23 日饮食、5小时59分钟睡眠、35分钟运动及排便；确认今天仍无这些补记记录；历史饮食编辑、排便否改是并刷新后仍归属 9 月 23 日。检查了 390px 手机宽度的补记弹窗。原生日期控件的 min/max 与保存校验均已验证。未在 iPhone Safari 真机上测试。

## V1.4 保留功能

- PCOS 生活方式记录与「饼饼服药记录」正式拆分。
- 移除 PCOS 内所有优思明卡片、周期、22:00 打卡、撤销和补记入口。
- 旧数据库中的 `pills` 数据不会被主动清空，但 PCOS 不再读取或操作它。
- 新增睡眠记录：小时 + 分钟、可选备注、当天记录、历史补记、重新记录及长按删除。
- 新增设备本机时间 21:00 开放的「今日分析」，无需刷新即可自动解锁。
- 今日分析包含彩色模块：今日概览、饮食结构、运动、体重、睡眠和身体状态。
- 今日分析按日期保存在 `dailyAnalyses`，当天数据变化后可以重新分析。
- 身体状态支持当天展示、历史补记和长按删除。
- 首页新增按日期查询的历史记录卡片，支持“昨天 / 今天”快捷切换，并集中查看饮食、运动、睡眠、体重、身体状态及已保存的当日分析。
- 保留原有本地食物数据库、自然数量解析和热量区间估算。
- 饮食录入新增可折叠的手动热量与分析：支持最低/最高 kcal、单一 kcal、分析备注及估算来源。
- 手动热量优先于本地食物库结果；饮食记录可再次编辑，21:00 今日分析也会优先汇总手动数据。
- 永久存储 key 继续固定为 `pcos90-data`。
- 保留一次性旧版迁移、稳定 fingerprint、删除 tombstone 和 JSON 合并导入。

## 数据兼容

旧数据缺少以下字段时会自动初始化为空数组，不覆盖现有记录：

- `poop`（V1.5 新增）
- `sleeps`
- `dailyAnalyses`
- `deleted`

现有 `settings`、`weights`、`foods`、`workouts`、`body` 等数据继续保留。程序不会清空 localStorage，也不会重新扫描已经完成迁移的旧 key。

## 备份

首页继续提供 JSON 导出和合并导入。导入时会尊重 `deleted` tombstone，已明确删除的记录不会自动恢复。
